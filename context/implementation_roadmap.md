# Implementation Roadmap

This sequence is a scope guard: complete and verify one phase before expanding. Each product stays independently deployable; this roadmap only implements the portfolio in this workspace unless an Ikigai repository is explicitly provisioned later.

## Phase 00 — Repository foundation

Confirm standalone portfolio boundary, runtime/tooling, environment conventions, static hosting assumptions, lint/type/build workflow, and structured content contracts. Deliver repository docs and a runnable minimal app scaffold.

## Phase 01 — Architecture and design system

Refine per-route rendering, caching, responsive typography/color/grid/spacing/texture/motion/accessibility tokens, performance instrumentation, and deployment headers. Record major decisions in ADRs.

## Phase 02 — Static content model

Define validated structured models for projects, about, education, achievements, experience, links, reviews, and Field Notes. Seed only owner-provided facts. Add content validation to build.

## Phase 03 — Public shell

Build semantic route shell for Home, Work, Lab, Field Notes, About, Contact; accessible responsive navigation/footer; route state and readiness/failure architecture; no final loader animation.

## Phase 04 — Hero and motion foundation

Implement Orbital Archive hero and recurring celestial motif in lightweight CSS/SVG, responsive and reduced-motion modes, and contextual cursor enhancement on pointer devices.

## Phase 05 — Work and project detail

Render project index/details from content data, evidence-based metadata and media, clear navigation, performance budgets. Miraaj Observatory only after relevant repository access and verified architecture.

## Phase 06 — About, education, and resume

Build editorial About, Built/Learning/Exploring evidence, education/involvement, interactive resume with conventional downloadable version.

## Phase 07 — Lab and Field Notes

Isolated AI Oracle and Snake; accessible lightweight experiments and engineering journal based on actual work. AI context excludes secrets.

## Phase 08 — Dynamic contact/reviews

Only when API repository is established: validated forms, rate limiting/spam defenses, secure storage, moderation queues, anonymous-review disclosures and synthetic identities.

## Separate future product tracks

Create Ikigai web and API as independent repositories when starting private product implementation. API foundation/auth precedes integrations, content publishing, monitoring, messages/reviews, notes, music, and vault. Vault receives a dedicated threat review before real data. Create native mobile repository only when mobile work starts, consuming stable versioned APIs.

## Exit criteria per phase

Required behavior is implemented, no invented user facts, relevant checks run, keyboard/reduced-motion/mobile behavior reviewed, budgets measured when meaningful, specs/context/progress updated, and any architectural change recorded as ADR. Do not start the next major feature until this is true.
