# UI Context

## Direction: The Orbital Archive

An art-directed digital experience made by an engineer: deep black, warm off-white, grayscale, one restrained accent, celestial geometry, generous negative space, grain/halftone used sparingly, editorial asymmetry, technical metadata, and typography-led composition.

## Supplied visual references

The supplied reference image centers a small seated figure against an enormous hand-drawn orbital sky, with monochrome grain and restrained editorial labeling. Carry forward the scale, quietness, orbit linework, and tactile surface as inspiration; do not copy the image or its social interface. The supplied 16-page PDF is an image-only mixed moodboard: use its select texture, astronomy, and interface observations as reference material, not as mandatory components or copied layouts. The owner separately specified that a video reference will govern the loading screen, so moodboard loading imagery does not finalize it.

## Typography and layout

Three roles only: display, interface, and technical monospace. Prefer self-hosted/subset fonts and robust fallbacks. Use responsive type scales and a consistent spacing/grid system. Compose each section deliberately; avoid giant generic headings, excessive rounded cards, skill badges, and generic SaaS conventions.

## Motif and surfaces

The celestial object is a recurring metaphor, not a repeated decorative stamp. Favor thin rules, measured surfaces, subtle texture, and a limited accent color. Ensure text contrast and keep textures behind content.

## Motion

Every movement communicates state, focus, hierarchy, or spatial continuity. Prefer short transform/opacity transitions; no constant movement or artificial waiting. Honor `prefers-reduced-motion`, pause hidden work, and provide touch equivalents. Cursor effects are desktop-only enhancements.

## Responsive composition

Desktop and mobile are intentionally composed, not just scaled. Protect reading order and navigation clarity; give controls practical touch targets. Hover never carries unique content or actions.

## Accessibility floor

Semantic HTML, skip link, keyboard operability, visible focus, labels and useful errors, accessible menu state, contrast, reduced motion, status announcements, and screen-reader text for visual/interactive experiments. No essential content only in canvas or hover.

## Loading

Only actual readiness and failure/fallback behavior until an owner reference video arrives. Never invent a final loading animation or artificial delay.

## Review questions

Does the composition have clear hierarchy and a route back? Is the motif purposeful? Does mobile get an intentional layout? Is motion useful and optional? Can the content be understood without effects? Does the implementation stay within budgets?
